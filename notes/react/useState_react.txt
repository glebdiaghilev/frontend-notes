чтобы данные в компоненте могли меняться и при этом автоматически 
меняли интерфейс в react существует такое понятие, как usestate.

обычная переменная в компоненте живет только один раз при первом рендере.
в нее можно что-то записать, но при следующем обновлении интерфейса react
просто пересоздаст компонент и перепишет ее в начальном значении. в итоге
все изменения потеряются.

состояние же хранится внутри самого react. когда оно меняется react сам 
запускает перерисовку компонента с обновленными данными, и не нужно руками
менять интерфейс.

для работы с состоянием есть специальная функция: useState, которая 
импортируется из react.

в react есть множество встроенных функций, имена которых начинается с 
префикса use, и такие функции называют хуками (hooks).

импортируется useState так:
import useState from 'react'

useState при использовании возвращает 2 значения:
1. текущее значение value;
2. функция для обновления значения setValue.

пример:
const [value, setValue] = useState(initialValue)

initialValue - передаем начальное значение

нельзя просто так изменять переменную напрямую, то есть,
если мы сделаем так:
let [value, setValue] = useState(initialValue)

value = '123'
то это будет неправильно, оно не будет работать по правилам
react и в целом это сломает интерфейс. поэтому всегда нужно
использовать setValue, только после такого обновления react
поймет наши действия.

хуки (hooks), в том числе useState, можно вызывать только
в теле функции компонента или внутри собственных хуков.

функции-хуки так же нельзя вызывать внутри условий, например:
if (true) {
    const [value, setValue] = useState(initialValue)
}
так нельзя! и эти функции нельзя вызывать внутри циклов и других
функций, например:
const onClick = () => {
    const [value, setValue] = useState(initialValue)
}
так нельзя! и уж тем более хуки нельзя использовать в jsx-разметке!

react ожидает, что хуки будут вызываться всегда в одном и том же 
порядке при каждом рендере.
