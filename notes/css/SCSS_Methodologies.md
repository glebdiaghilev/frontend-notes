# Архитектура SCSS и глобальные стандарты: от BEM до BigTech-монорепозиториев

## 🧱 1. БЭМ (Блок, Элемент, Модификатор)

Методология БЭМ является фундаментальным стандартом в веб-разработке. Она создана для изоляции интерфейсных модулей, что позволяет полностью решить проблему глобальной области видимости CSS. Главная идея — сделать компоненты независимыми, чтобы их можно было безболезненно переносить в любую часть проекта или использовать повторно на других сайтах.

### Схема связей и иерархия в структуре
```text
[ Блок: .c-card ] (Родительский контейнер, создает независимую область видимости)
       │
       ├─── [ Элемент: .c-card__image ] (Зависимый дочерний узел, контекст блока)
       ├─── [ Элемент: .c-card__title ] (Зависимый дочерний узел, контекст блока)
       │           │
       │           └─── [ Модификатор: --large ] (Флаг оформления: изменяет размер текста)
       │
       └─── [ Элемент: .c-card__button ] (Зависимый дочерний узел, контекст блока)
                   │
                   └─── [ Модификатор: --disabled ] (Флаг состояния: делает кнопку серой)
```

### Анатомия составного класса
```text
  c-card__title--large
  │  │     │      │
  │  │     │      └─── Модификатор (определяет конкретный вариант или состояние)
  │  │     └────────── Элемент (внутренний дочерний узел в домене блока)
  │  └──────────────── Имя Блока (основа и идентичность независимого компонента)
  └─────────────────── Префикс пространства имен (определяет системную роль класса)
```

### Продвинутая реализация на SCSS
В масштабных BigTech-проектах **строго не рекомендуется** злоупотреблять склеиванием селекторов через амперсанд (`&__element`). Склеивание классов на этапе компиляции лишает команду возможности использовать глобальный текстовый поиск по кодовой базе (IDE не сможет найти класс `.c-card__title`, если он записан как `&__title`). 

```scss
// 👍 Стандарт индустрии: явное написание классов для удобства глобального поиска
.c-card {
  display: flex;
  flex-direction: column;
  background-color: var(--surface-primary);
  border-radius: 8px;
  
  // Класс написан полностью — это упрощает рефакторинг и поиск по коду
  .c-card__title {
    font-size: 1.25rem;
    font-weight: 700;
    
    // Для модификаторов амперсанд использовать можно, так как они локальны
    &--large {
      font-size: 2rem;
    }
  }

  .c-card__button {
    padding: 0.75rem 1.5rem;
    
    &--disabled {
      opacity: 0.5;
      pointer-events: none;
    }
  }
}
```

## 📦 2. SMACSS (Масштабируемая и модульная архитектура для CSS)

Методология SMACSS предлагает распределять правила CSS по пяти жестко разграниченным категориям (слоям). Это разделение ответственности на уровне таблиц стилей помогает разработчикам быстро определять, куда именно должен быть записан новый код и как он повлияет на остальную систему.

### Схема распределения веса и логических слоев
```text
📂 [ 1. BASE ]        --> Сбросы стилей, правила для чистых HTML-тегов (body, input)
       │
       ▼
📂 [ 2. LAYOUT ]      --> Каркасные сетки страницы (шапка, подвал, боковые панели)
       │
       ▼
📂 [ 3. MODULE ]      --> Модульные независимые UI-компоненты (.card, .modal, .slider)
       │
       ▼
📂 [ 4. STATE ]       --> Интерактивные состояния элементов (.is-active, .is-collapsed)
       │
       ▼
📂 [ 5. THEME ]       --> Правила темизации (ночной режим .theme-dark, контрастный стиль)
```

### Практический пример разделения кода по SMACSS
```scss
// 1. Базовый слой (_base.scss) — стилизует теги без классов
body {
  font-family: 'Inter', sans-serif;
  line-height: 1.5;
  color: #333;
}

// 2. Слой раскладки (_layout.scss) — макроструктура и сетка сайта
.l-header {
  display: grid;
  grid-template-columns: auto 1fr;
  position: sticky;
}

// 3. Модульный слой (_modules.scss) — ядро интерфейса (компоненты)
.c-product-alert {
  border: 1px solid transparent;
  border-radius: 4px;
  padding: 1rem;
}

// 4. Слой состояний (_states.scss) — динамика, управляемая через JS
.c-product-alert.is-hidden {
  display: none;
}

// 5. Тематический слой (_themes.scss) — цветовые схемы окружения
.theme-dark .c-product-alert {
  background-color: #222;
  color: #fff;
}
```

## 🔺 3. ITCSS (Inverted Triangle CSS / Перевернутый треугольник CSS)

ITCSS — это вершина архитектурной мысли в мире CSS/SCSS, активно применяемая в BigTech (Google, Meta). Она организует код в виде перевернутого треугольника: от самых абстрактных, глобальных и «слабых» правил на вершине до точечных, высокоспецифичных и «сильных» утилит у основания. Такой подход полностью исключает появление конфликтов специфичности (когда один стиль случайно перебивает другой).

```text
       СВОЙСТВА КАСКАДА:                                  АРХИТЕКТУРА СЛОЕВ:
 
 Высокий охват / Низкий вес                    ▼ СЛОЙ 1: Settings (Глобальные токены и переменные)
      ┌───────────────┐                        ▼ СЛОЙ 2: Tools (Глобальные миксины и функции)
       \             /                         ▼ СЛОЙ 3: Generic (Сбросы стилей, Reset/Normalize)
        \           /                          ▼ СЛОЙ 4: Elements (Оформление чистых тегов)
         \         /                           ▼ СЛОЙ 5: Objects (Бездизайнерские сетки, структуры)
          \       /                            ▼ СЛОЙ 6: Components (БЭМ-модули с дизайном)
           \     /                             ▼ СЛОЙ 7: Trumps (Утилитарные классы с !important)
            \   / 
             \ /                               
 Низкий охват / Высокий вес
```

### Конвейер прохождения стилей сквозь слои
Стили компилируются строго в указанном порядке. Код течет сверху вниз, плавно увеличивая свою силу (специфичность), что гарантирует предсказуемость каскада.

```text
[ Settings ]   --> v.cls-brand-primary, v.font-size-base (Входные данные, не генерируют CSS)
     │
     ▼
[ Tools ]      --> @mixin breakpoint-up(), @function rem() (Инструменты, не генерируют CSS)
     │
     ▼
[ Generic ]    --> * { box-sizing: border-box; }, html { scroll-behavior: smooth; }
     │
     ▼
[ Elements ]   --> h1 { margin-bottom: 1rem; }, table { width: 100%; }
     │
     ▼
[ Objects ]    --> .o-container { inline-size: 100%; }, .o-flex-row { display: flex; }
     │
     ▼
[ Components ] --> .c-button { color: #fff; }, .c-avatar { border-radius: 50%; }
     │
     ▼
[ Trumps ]     --> .u-text-truncate { overflow: hidden !important; }
```

## 🗂️ 4. Архитектурный паттерн структуры папок 7-1

Мировой стандарт физической организации файлов на диске для препроцессора Sass. Проект разбивается на 7 изолированных папок и 1 главный файл (`main.scss`). Ключевое правило: главный файл проекта не должен содержать ни одной строчки чистого CSS-кода — он выступает исключительно диспетчером и сборщиком импортов.

```text
📁 src/scss/
│
├── 📁 abstracts/       # Слои Settings и Tools (Только логика проекта)
│   ├── _variables.scss # Дизайн-токены (семантические карты цветов, шкалы отступов)
│   ├── _mixins.scss    # Кроссбраузерные конструкции и обертки медиа-запросов
│   └── _functions.scss # Математические утилиты перевода величин (например, px в rem)
│
├── 📁 base/            # Слои Generic и Elements (Фундамент приложения)
│   ├── _reset.scss     # Нормализация отображения элементов в разных браузерах
│   └── _typography.scss# Глобальные правила для текста и заголовков
│
├── 📁 layout/          # Слой Objects (Макроструктура и сетка макета)
│   ├── _header.scss    # Стили верхней панели навигации
│   ├── _footer.scss    # Матрица подвала сайта
│   └── _grid.scss      # Абстрактные сетки колонок
│
├── 📁 components/      # Слой Components (Капсулированные UI-элементы)
│   ├── _button.scss    # Изолированные стили всех видов кнопок
│   ├── _card.scss      # Сложные карточки интерфейса
│   └── _nav.scss       # Локальные деревья меню
│
├── 📁 pages/           # Непереиспользуемые стили для конкретных уникальных страниц
│   ├── _home.scss      # Специфичные блоки для главной страницы сайта
│   └── _dashboard.scss # Архитектура личного кабинета пользователя
│
├── 📁 themes/          # Модули глобальной модификации визуального окружения
│   ├── _light.scss     # Настройки стандартной дневной темы
│   └── _dark.scss      # Переопределение цветов для ночного режима
│
├── 📁 vendors/         # Внешний неизмененный код библиотек
│   └── _swiper.scss    # Стили для готового плагина слайдера
│
└── 📄 main.scss        # Главный узел и точка сборки проекта
```

### Схема сборки кодовой базы через модульную систему `@use`
```text
📄 main.scss (Точка сборки)
 │
 ├──► @use 'base/reset';         ──┐
 ├──► @use 'base/typography';     │
 ├──► @use 'layout/header';       ├──► Компилятор собирает все файлы по цепочке
 ├──► @use 'layout/grid';         │    и выдает один минифицированный файл стилей:
 ├──► @use 'components/button';   │    dist/css/main.css
 └──► @use 'components/card';    ──┘
```

## 🏷️ 5. Пространства имен BigTech (Namespaces)

В крупных компаниях со множеством команд разработчиков (Google, Meta, GitHub) использование чистого БЭМ может приводить к конфликтам имен. Чтобы этого избежать, к именам классов добавляются жесткие системные префиксы (Namespaces). Это позволяет мгновенно понять назначение элемента, глядя только на HTML-разметку.

```text
                    ГЛОБАЛЬНАЯ ИЕРАРХИЯ ПРОСТРАНСТВ ИМЕН
             
       ┌───────────────────────┼───────────────────────┐
       │                       │                       │
 📦 [ c- ] Component     🧱 [ o- ] Object        🛠️ [ u- ] Utility
   Уникальный дизайн.      Агностический скелет.   Атомарное действие.
   Зависит от тем.         Не имеет цветов/фонов.  Содержит !important.
   Пример: .c-modal        Пример: .o-flex-row     Пример: .u-display-none
       │                       │                       │
       └───────────────────────┼───────────────────────┘
                               │
                       ┌───────┴───────┐
                       │               │
                 ⚡ [ is- / has- ]     ⚙️ [ js- ]
                 Динамические          Технические триггеры JS.
                 состояния элементов.  Полный запрет на
                 Пример: .is-active     стилизацию внутри SCSS.
                                       Пример: .js-modal-trigger
```

### Скоординированная работа префиксов в HTML-коде
```html
<div class="o-layout__item c-user-card is-selected u-margin-bottom-20">
  <!--
    o-layout__item    --> Выделяет структуру и ширину в рамках глобальной сетки (слой Objects)
    c-user-card       --> Окрашивает фон, добавляет тени, скругляет углы (слой Components)
    is-selected       --> Подсвечивает элемент золотой рамкой при клике (слой State)
    u-margin-bottom-20--> Принудительно отодвигает элемент снизу на 20px (слой Trumps)
  -->
</div>
```

## 🚀 6. Современная модульная архитектура Sass

> ⚠️ Старый синтаксис `@import` признан устаревшим (deprecated) командой разработчиков Sass. В современном Enterprise-коде используется строгая инкапсуляция через правила `@use` и `@forward`. Это защищает глобальную область видимости от засорения и исключает дублирование стилей при компиляции.

### Схема изоляции модулей и работа с зависимостями
```scss
// src/scss/abstracts/_variables.scss
$color-primary: #0284c7;
$color-accent: #f43f5e;
$border-radius-base: 8px;

// src/scss/components/_button.scss
// Подключаем файл как изолированный модуль с коротким псевдонимом 'v'
@use '../abstracts/variables' as v; 

.c-button {
  background-color: v.$color-primary; // Доступ к переменной через пространство имен
  border-radius: v.$border-radius-base;
  padding: 0.5rem 1rem;
  transition: background-color 0.2s ease;
  
  &:hover {
    background-color: v.$color-accent;
  }
}
```

## ⚙️ 7. Автоматический контроль стандартов (Stylelint)

Чтобы человеческий фактор не нарушал архитектуру, в BigTech используют линтеры. Они автоматически сканируют написанный SCSS-код при каждом сохранении файла или коммите и блокируют сборку проекта, если разработчик нарушил правила вложенности или использовал некорректный класс.

### Конфикаруция файла `.stylelintrc.json` для Production
```json
{
  "extends": [
    "stylelint-config-standard-scss"
  ],
  "rules": {
    "max-nesting-depth": 3,
    "selector-max-id": 0,
    "selector-max-compound-validators": 3,
    "selector-class-pattern": "^[c|o|u|l]-(?:[a-z0-9]+)?(?:__[a-z0-9]+)?(?:--[a-z0-9]+)?$|^(is|has)-[a-z0-9-]+$|^js-[a-z0-9-]+$",
    "scss/at-import-partial-extension": "never"
  }
}
```
*Разбор ключевых правил конфигурации:*
*   `max-nesting-depth: 3` — запрещает вложенность элементов в SCSS глубже 3 уровней. Защищает от перегруженных селекторов и падения производительности рендеринга.
*   `selector-max-id: 0` — полностью запрещает использовать `#id` в качестве селекторов для стилей (айдишники имеют слишком высокий приоритет и ломают каскад).
*   `selector-class-pattern` — регулярное выражение, которое автоматически проверяет все классы в проекте. Оно пропустит только те имена, которые начинаются с правильного префикса (`c-`, `o-`, `u-`, `l-`, `is-`, `has-`, `js-`) и оформлены строго по БЭМ. Любая попытка написать класс `.block_element` или `.button` вызовет ошибку линтера.
